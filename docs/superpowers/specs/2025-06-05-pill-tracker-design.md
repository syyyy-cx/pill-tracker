> 一款为中国用户打造的二人专属药品监督 PWA
> 创建日期：2025-06-05 | 作者：Claude + hazie

## 1. 概述

专为情侣/伴侣设计的轻量药品监督 Web 应用。支持两人绑定、药品打卡、AI 鼓励、契约竞赛、成就系统、实时聊天，以 PWA 形式部署，可添加到手机桌面使用。

### 核心目标

- 帮助双方坚持按时吃药，互相关心
- 用游戏化（契约 + 成就）增加动力
- 在中国网络环境下流畅使用，无需备案

### 目标用户

- 无编程经验的普通用户
- 需要部署者在 GitHub 和 Cloudflare 上按步骤操作

## 2. 技术架构

### 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端框架 | **React 18 + Vite** | 轻量、生态成熟 |
| UI 样式 | **手写 CSS (CSS Modules)** | 零依赖，极致轻量 |
| PWA | **vite-plugin-pwa + Workbox** | 离线缓存、Service Worker |
| 后端 API | **Cloudflare Workers** | 边缘计算，免费额度慷慨 |
| 数据库 | **Cloudflare D1 (SQLite)** | 免费 5GB，关系型数据库 |
| 实时通信 | **Durable Objects** | WebSocket 实时聊天 |
| 推送通知 | **Web Push API** | 浏览器推送 |
| 用户认证 | **JWT (简单 Token)** | 两人药局无需复杂 OAuth |
| AI 功能 | **DeepSeek API** | 国内可用，注册送额度 |

### 部署架构

```
GitHub Repository
       │
       ▼  (自动部署)
Cloudflare Pages ──► 静态资源 (React PWA)
       │
       ▼
Cloudflare Workers ──► API 服务
       │
       ▼
Cloudflare D1 ──────► 数据库
       │
       ▼
Durable Objects ────► 实时聊天
```

### 为什么选 Cloudflare

- 🆓 免费额度：Workers 10 万请求/天、D1 5GB、Pages 无限带宽
- 🇨🇳 国内可访问：`*.pages.dev` 域名在国内可直接访问
- 📝 不需要 ICP 备案：国际服务无需备案
- 🔗 GitHub 集成：push 代码自动部署

## 4. 页面设计

### 4.1 首页——打卡页（默认页）

**从上到下结构：**

1. **顶部问候区**
   - 根据时段显示"早安/午安/晚安 🌅"
   - 用户昵称
   - 每日一句温暖的话（手动维护一批）
   - 右上：对方的打卡状态 + 连续打卡天数

2. **今日进度条**
   - "今日打卡 X/Y" + 按时/迟到计数
   - 彩色进度条

3. **药品列表**（按状态分组）
   - 🟢 **已打卡** — 绿色背景，显示打卡时间，💌按钮可看当时附言
   - 🔵 **待打卡（固定时间）** — 蓝色边框，显示 ⏰ 应吃时间

   - 🔴 **已迟到** — 红色背景，显示迟到时长，"补卡"按钮

4. **底部 Tab 导航**（固定）
   - 💊 打卡 | 📊 统计 | 🏆 成就 | 💬 消息 | 📜 契约

**交互：**
- 点击药品卡片的"已吃"按钮 → 打卡确认 → 打卡动画 → 弹出留言框

## 5. 功能流程

### 5.1 打卡流程

```
用户进入首页
  → 看到今日药品列表
  → 点击药品卡片上的"已吃"按钮
  → 打卡动画（跳动的心形 ❤️）
  → 弹出留言框（可选）
  → 提交 → 状态更新为"已打卡"
  → 检查成就解锁条件
  → 消息流中新增打卡通知
```

**按时判断逻辑：**
- 固定时间：打卡时间 ≤ 设定时间 + 30 分钟缓冲 → 按时；否则迟到
- 灵活时段：打卡时间 ≤ 截止时间 → 按时；否则迟到
- 当天未打卡 → 漏打（次日凌晨自动标记）

### 5.2 AI 鼓励流程

```
每晚 21:00（由 Cron Worker 触发）
  → 读取当日双方的打卡数据
  → 构造 prompt（包含打卡率、按时率、连续天数等）
  → 调用 DeepSeek API
  → 生成个性化温暖鼓励文本
  → 以系统消息形式推送到聊天流
  → 触发浏览器推送通知
```

Prompt 示例：
```
你是一个温暖的朋友。根据以下数据生成一段 100 字以内的鼓励话语：
- 小A：打卡 4/4，按时 4，连续 7 天全勤
- 小B：打卡 3/4，按时 2，迟到 1，连续 3 天
要求：温暖、个性化、不评价好坏、重在鼓励。用中文，语气亲切。
```

### 5.3 契约结算流程

```
到达结算时间（日/周/月）
  → 统计期内双方的打卡得分
  → 比较分数
  → 确定胜者/败者
  → 推送结算结果到聊天
  → 触发"契约胜者"成就检查
```

## 6. 安全与隐私

- 两人数据仅彼此可见
- JWT Token 存储在 localStorage
- WebSocket 连接验证 Token
- 邀请码 7 天过期，防止滥用
- 不存储敏感个人信息（不需要手机号/邮箱）
- AI 请求时仅发送打卡统计数据，不发送姓名等隐私信息

## 8. 用户部署步骤

部署者需完成的步骤（我负责全部代码，用户只需操作）：

1. **注册 GitHub** → 创建一个仓库
2. **注册 Cloudflare** → 进入 Workers & Pages
3. **连接 GitHub** → 授权 Cloudflare 访问仓库
4. **部署** → Cloudflare 自动构建部署
5. **配置 D1 数据库** → 在 Cloudflare 创建数据库并关联
6. **配置 AI API Key** → 注册 DeepSeek 获取 API Key
7. **初始化数据库** → 运行一次初始化 SQL
8. **打开链接** → 手机浏览器打开 → 添加到桌面

## 10. 设计原则

- **移动端优先**：所有页面以手机屏幕尺寸设计
- **轻量极简**：零 UI 框架依赖，手写 CSS，极致加载速度
- **离线优先**：PWA 缓存策略确保离线可用
- **温暖氛围**：渐变色彩、圆角卡片、柔和阴影、爱心元素
- **低于 100ms**：Workers 边缘计算确保 API 响应速度
